# 医护供给规划版本库

维护执业医师、注册护士和基层服务能力的区域规划**假设审议、情景共识与发布复现**。

`contracts/workforce_scenario.json` 是公共基线：2030 年目标（执业医师 500 万、注册护士 700 万，医师不含执业助理医师）、统计定义、规范单位、六个规范变量、引用时效与置信区间政策、表决与发布规则。所有提交、情景、发布都引用同一基线编号与契约指纹。契约只含公开统计定义，不含任何真实个人资料。

## 要解决的问题

各地围绕 2030 年目标提交规划时，总数看似达标，背后却使用不同的退休率、培训完成率、跨区流动与效率假设。本服务的纪律是：

1. **分歧先于加总**：医院、基层机构、教育部门、财政部门分别提交假设，每条必须带来源、适用地区、时间范围和 95% 置信区间。
2. **不可比不相加**：单位冲突、定义不一致、引用过期、缺置信区间、同格竞争假设、全国/地方格混用、覆盖不齐——一律先进澄清，不进入求和。
3. **情景显式化**：只有兼容假设能组合成候选情景；点估计测算 + 单变量敏感性分析，记录哪些变量改变达标结论。
4. **审议留痕**：评审成员披露利益关系后才能投票；反对票必须附理由；少数方案随版本永久保存。
5. **发布即冻结**：冻结输入快照、计算程序指纹、审批记录；已发布版本不可变，新数据另起修订版，形成修订链。
6. **同快照可复现**：决策者查看任一指标都能看到假设链、未解决分歧、替代情景，并在冻结快照上重算出相同结果。
7. **不碰个人档案**：服务只接受聚合统计；身份证号、病历号、患者标识等字段在入口即被拒收。

## 领域模型

- 规范变量（每支队伍 × 每个地区各一条）：
  - `stock` 基期在岗存量（persons）
  - `retirement_rate` 年退休/减员率（fraction_per_year）
  - `training_intake` 年均培训入口（persons_per_year）
  - `completion_rate` 培训完成率（fraction，已含培训周期滞后）
  - `net_inflow_rate` 年跨区净流入率（fraction_per_year；全国必须为 0，省际调入调出配对轧平）
  - `efficiency_index` 服务效率指数（2025=1）
- 递推模型（确定性、无外部依赖）：

  ```
  stock_t = stock_{t-1} × (1 − retirement_rate + net_inflow_rate) + training_intake × completion_rate
  有效服务能力_2030 = stock_2030 × efficiency_index
  ```

- 地区层级：`CN` 为全国，`CN-BJ` 等为省级；全国格与地方格不得在同一情景混用。
- 引用时效：评审日（2026-09-14）往前 3 年，早于 2023 年的来源判为过期。

## 工作流

```
公共基线 (contracts/workforce_scenario.json)
   │  契约指纹
   ▼
四方提交假设 ──► 门禁校验（单位/定义/时效/区间/时间/隐私）
   │                     │
   │ active              ▼ clarification（更正 / 撤回 / 定义分歧经背书说明）
   ▼
研究人员组合候选情景 ──► 兼容性检查 ──► 测算 + 敏感性分析（结论翻转变量）
   ▼
开评审 ◄── 评审员登记并披露利益关系
   │  投票（反对须附理由；可挂少数方案）
   ▼
关闭计票（四方法定人数 + 多数决）── 通过 ──► 发布 V1（冻结输入/程序指纹/审批记录）
                                              │ 新数据
                                              ▼
                                     另起修订版 V2（V1 不可变，修订链可溯）
```

## HTTP 接口

| 方法与路径 | 说明 |
| --- | --- |
| `GET /health` | 服务身份 |
| `GET /baseline` | 公共基线内容与契约指纹 |
| `POST /assumptions` | 提交假设；不合法返回 `status=clarification` 与问题清单 |
| `GET /assumptions?status=…` | 假设列表（可按状态/队伍/地区过滤） |
| `POST /assumptions/:id/clarify` | 澄清处理：`correct` / `withdraw` / `justify` |
| `POST /scenarios` | 用 `assumption_ids` 组合候选情景（不兼容也保留并附错误，不产出结果） |
| `GET /scenarios/:id` | 情景、测算结果与敏感性报告 |
| `POST /reviewers` · `POST /reviewers/:id/disclosures` | 评审员登记与利益披露 |
| `POST /reviews` | 对兼容情景开评审（可带 `revision_of_release`） |
| `POST /reviews/:id/votes` | 投票（`approve`/`oppose`/`abstain`；反对须附理由，可挂少数方案） |
| `POST /reviews/:id/close` · `POST /reviews/:id/publish` | 计票与发布冻结 |
| `GET /releases` · `GET /releases/:id` | 发布版本（含完整冻结快照） |
| `GET /releases/:id/archive` · `POST /releases/import` | 归档导出 / 归档导入（导入做三重完整性核验） |
| `POST /releases/:id/replay` | 在冻结快照上重放：输入完整性、程序指纹、结果指纹 |
| `GET /releases/:id/metrics/physicians_2030`（或 `nurses_2030`） | 决策者指标视图：值、假设链、敏感性翻转、未决分歧、少数方案、替代情景、复现凭证 |

## 使用

```bash
npm run check     # 装配演示数据并自检（含冻结重放）
npm test          # 49 项契约/领域/HTTP 测试
npm start -- --port 8000          # 启动空服务
npm start -- --port 8000 --seed   # 启动并装入演示数据
node src/service.js --demo        # 打印演示全流程 JSON
```

演示数据（`src/app.js` 的 `seedDemo`）覆盖：教育部门误以百分数提交完成率 → 单位冲突进澄清 → 更正；夹带身份证号的提交被隐私红线拒收；2020 年旧数据进澄清；基准情景 V1 表决（3 赞成 1 反对，财政方附「效率提升」少数方案）并发布；2030 年医师在 V1 差约 16.8 万未达标、护士达标；V2 以 2026 中期效率数据另起修订版，医师结论翻转为达标；V1 冻结快照重放结果指纹一致。

## 复现凭证的三层指纹

- **契约指纹**：基线目标、定义、单位、变量与政策的规范化哈希；
- **输入指纹 / 假设内容指纹**：情景所用每条假设的内容哈希与集合哈希；
- **程序指纹**：参与计算的 `src/*.js`（引擎版本 1.0.0）哈希；
- **结果指纹**：在特定模型与输入下测算结果的规范化哈希。

`replay` 同时核验三层，任一不符都会明确报告（输入被改、程序变更、结果不一致）。
